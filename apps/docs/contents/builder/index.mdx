# Builder

Builder is the unified pipeline (in `packages/builder`) that turns raw assets into the manifest and thumbnails the SPA consumes. It mirrors the “overview → entrypoint → options” cadence used by Vercel’s AI Gateway docs.

## What you get

- 600 px JPEG thumbnail per photo + ThumbHash (`thumbHash`).
- `photos-manifest.json` sorted by capture time, plus `cameras[]`/`lenses[]` dictionaries.
- EXIF (incl. Fujifilm/Sony recipes), GPS, tone analysis, HDR, Motion Photo, Live Photo markers, and embedded XMP keywords/regions.
- Optional plugins to sync or rewrite outputs (e.g., upload thumbnails, repo cache).

## XMP regions

When photos contain embedded XMP packets, Builder now extracts:

- `keywords[]` from `dc:subject`, `lr:hierarchicalSubject`, and `lr:weightedFlatSubject`
- `regions[]` from Lightroom/MWG region metadata (`mwg-rs:Regions`)

Those values are written into each manifest item and consumed by the web viewer. The viewer can show region boxes immediately on the thumbnail placeholder, then keep them aligned after the full-resolution image loads.

XMP extraction is configured through `system.processing.xmp` in `builder.config.ts`, with separate `keywords` and `regions` booleans. Both default to `true`.

Current expectations and caveats:

- Only **embedded XMP inside the image file** is parsed. Standalone `.xmp` sidecars are not read.
- Region coordinates are normalized into manifest output, but front-end alignment still depends on EXIF orientation handling for the source image.
- The viewer currently supports the common rotation orientations (`3`, `6`, `8`). Mirrored EXIF orientations are not handled yet.

## How to run it

- **Quick switches:** per-run CLI flags (incremental, force, force-manifest, force-thumbnails, no-ui).
- **Defaults:** `builder.config.ts` for storage, concurrency, logging, plugins.

## Prerequisites

- Node.js (workspace default) and **Perl** (required by `exiftool-vendored`).
- A valid `builder.config.ts` with at least one storage provider.
